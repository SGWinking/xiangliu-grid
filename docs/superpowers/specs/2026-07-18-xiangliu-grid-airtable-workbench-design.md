# 相柳网格 Airtable 风格专业工作台改版规格

**日期：** 2026-07-18

**基线提交：** `db3890f`

**设计依据：** `F:\AI相关文件\awesome-design-md-main\awesome-design-md-main\design-md\airtable\DESIGN.md`

**选定方向：** A「专业工作台」

## 1. 目标

把相柳网格从“多个长表单堆在同一页”改成清晰、稳定、适合高频生产的本地图片工作台，同时修复本轮审查中已经能够稳定复现的功能、安全和交付问题。

完成后的工具应满足以下结果：

- 五个工作流都能从固定导航进入：图块裁切、局部回贴、整图拼合、行列裁切、分辨率导出。
- 参数区、预览区、结果与运行状态各司其职；长任务期间用户能看到正在做什么、是否成功、失败原因和输出位置。
- 界面严格使用指定 `DESIGN.md` 的色彩、排版、圆角、间距和按钮层级，不保留当前红色按钮铺满、零圆角、重阴影、粗体大字和深色主题。
- 后端拒绝会造成路径越界、数百万图块、超大输出或覆盖文件的危险输入。
- 从 `http://127.0.0.1:8765/` 使用时稳定；若保留 `file://` 模式，则必须真正通过 CORS 和预检测试，不能只改前端 URL。
- 源码、说明文档与最终打包 EXE 功能一致。

## 2. 本次范围

### 2.1 必须完成

1. 重构 `web/index.html` 的页面结构和样式，但保留现有五条业务流程及后端 API 语义。
2. 恢复“局部回贴”导航入口；当前 `patchPage` 已存在但没有任何标签按钮，属于不可达功能。
3. 为后端建立统一请求校验、路径约束、错误响应和 CORS 策略。
4. 修复切图参数失控、上传覆盖、超大缩放和整文件读取造成的资源风险。
5. 为关键后端行为和前端结构补充自动化回归测试。
6. 更新 README、使用说明、启动脚本版本号和打包产物。

### 2.2 不在本次范围

- 不改变接缝平衡、低频颜色场、Lab Reinhard 等图像算法的数学模型。
- 不引入 React、Vue、前端构建工具或数据库；继续保持单 HTML + Python 标准 HTTP 服务的轻量结构。
- 不新增 AI 超分辨率、云端上传、账号系统或多人协作。
- 不重写 manifest 格式，不破坏已经生成的历史任务。

## 3. 已确认问题与处理边界

### 3.1 必须修复

#### P0-1 静态文件路径越界

当前 GET 回退路径直接拼接 `WEB_ROOT / parsed.path`。使用原始请求 `GET /..\server.py` 已实测返回 200，并读出完整 `server.py`。

处理：所有静态路径先解码并 `resolve()`，只允许目标位于 `WEB_ROOT`；未知路径返回 404。`/assets/` 和 `/outputs/` 使用各自独立白名单根目录。

#### P0-2 切图参数可把服务拖死

当前 `overlap >= long_edge` 时，步长被静默压成 1。用 2048 × 2048 图片、块尺寸 256、重叠 256 已实测接口超时；同类输入会推导出数百万图块。

处理：后端强制 `0 <= overlap < long_edge`，并限制行数、列数、总图块数和工作画布像素。校验失败返回 400 和可直接显示给用户的中文说明。

#### P0-3 `file://` 兼容不完整

前端虽将 API 指向 `127.0.0.1:8765`，但服务没有 `OPTIONS`，预检实测返回 501，响应也没有 `Access-Control-Allow-Origin`。

处理：推荐入口仍是本地 HTTP。服务实现受限 CORS，仅允许 `http://127.0.0.1:*`、`http://localhost:*` 和 `Origin: null`；实现 `OPTIONS`。若测试证明浏览器对 `file://` 仍不稳定，则删除直接双击 HTML 的暗示，只保留启动器打开 HTTP 页面。

#### P0-4 局部回贴功能不可达

`patchPage` 及完整事件代码存在，但导航只有四个标签。

处理：固定左侧流程导航增加“局部回贴”，顺序为裁切 → 回贴 → 拼合 → 行列裁切 → 分辨率导出。

#### P0-5 上传和输出缺少资源与覆盖保护

上传没有大小上限，同名文件直接覆盖；JSON 请求也按任意 `Content-Length` 读取。分辨率导出最高 16 倍且没有像素上限，可能耗尽内存。`serve_file()` 对文件执行 `read_bytes()`，大文件会一次性进入内存。

处理：

- JSON 请求上限 1 MB，上传默认上限 1 GB，并在错误信息中说明限制。
- 上传文件名先 URL 解码再清洗；同名文件自动添加序号，不覆盖旧文件。
- 分辨率导出限制最大边和总像素，提交前在界面显示目标尺寸与风险提示。
- 静态文件和输出文件分块传输，不再整文件读入内存。

#### P0-6 源码与打包版本不一致

当前 EXE 和安装包生成于 2026-06-25，分辨率导出源码修改于 2026-07-04；打包版本不包含当前完整功能。根目录启动脚本仍显示 v0.3.0。

处理：源码验证完成后重新打包 v0.5.0，启动脚本、页面、服务、README 和使用说明统一版本。

### 3.2 建议本次一起修复

- 上传的中文文件名当前被保存为 `E4_BA...` 形式；改为解码后保留中文。
- PNG/TIFF/JPEG/WebP 的“质量”含义不同；仅在 JPG/WebP 下启用质量输入。
- 切图强制转 RGB 会丢失透明通道和高位深信息；界面明确提示，后端在可安全保留时保留模式，否则要求用户确认转换。
- 操作错误目前只写进底部日志，用户很难看到；改为就近错误消息 + 顶部状态条 + 详细日志。
- `setBusy()` 当前禁用全站所有按钮；改为只锁当前任务操作，导航和取消/查看日志仍可用。
- 清空按钮当前会清除其他工作流字段；改为只清理当前工作流，并二次确认是否同时清除关联路径。
- 历史记录并发写入缺少原子性；采用临时文件写入后替换，并加进程内锁。

## 4. 信息架构

### 4.1 顶部栏

高度 64 px，白色背景，底部 1 px `{colors.hairline}`。

- 左侧：Logo、Xiangliu Grid、版本号与“本地图片工作台”。
- 中间不放主导航，避免与左侧流程栏重复。
- 右侧：服务状态、打开输出目录、当前流程的唯一主操作。
- 删除深色主题按钮。指定设计规范要求白色画布和始终为浅色的顶部导航。

### 4.2 左侧流程导航

宽 208 px，背景 `{colors.surface-soft}`，与主区域之间使用 1 px 边线，不使用阴影。

每个入口含序号、名称和一句短说明。当前入口使用 `{colors.primary}` 近黑背景和白字；其余入口保持透明。状态点显示未开始、进行中、完成、警告，不用额外彩色按钮。

### 4.3 参数面板

桌面宽 360 px，白底，独立滚动。按“输入 → 参数 → 输出”分组，每组之间用 24 px 间距和细边线分隔。

- 标签 14 px，字重 500。
- 输入高 44 px、6 px 圆角、1 px hairline；聚焦用 `{colors.info-border}`。
- 主按钮近黑、12 px 圆角、每个视口只保留一个。
- 次按钮白底描边；危险或不可逆动作才使用 `{colors.signature-coral}`。
- 不实现 hover 样式，只实现 Default、Active/Pressed、Focus、Disabled。

### 4.4 工作区

占剩余宽度，包含：

1. 预览工具条：标题、当前图片名、缩放/适应窗口控制。
2. 大预览画布：自适应图像比例，网格、编号和框选覆盖在同一坐标系统。
3. 关键统计条：只显示当前流程最有用的 4 项，不再固定展示 8 张大卡。
4. 结果面板：默认折叠，完成或失败时自动展开；路径可复制，输出目录可直接打开。
5. 详细日志抽屉：保留技术信息，但不作为唯一反馈渠道。

### 4.5 响应式

- `>= 1280 px`：208 px 导航 + 360 px 参数 + 弹性工作区。
- `1024–1279 px`：导航缩为图标/短标签，参数面板 320 px。
- `768–1023 px`：左侧导航变为顶部横向流程条，参数和预览上下排列。
- `< 768 px`：单列；流程导航为可横向滚动的标签，所有按钮至少 44 × 44 px，成组输入改为单列。

## 6. 状态与错误处理

每条工作流统一为以下状态：`idle`、`ready`、`running`、`success`、`warning`、`error`。

- `idle`：显示下一步提示，不显示空白的 8 项统计。
- `ready`：输入有效，深绿状态条给出即将输出的尺寸/块数。
- `running`：主按钮显示动作文本与进度状态，只锁当前流程；长任务提供已处理块数。
- `success`：显示输出摘要、路径复制和打开目录按钮。
- `warning`：高分辨率、颜色模式转换、存在旧输出等需要用户判断的情况。
- `error`：错误靠近相关字段显示；顶部状态条给出人话摘要；日志保留原始技术详情。

后端错误统一结构：

```json
{
  "error": {
    "code": "INVALID_OVERLAP",
    "message": "重叠像素必须小于图块尺寸。",
    "field": "overlap",
    "detail": "long_edge=256, overlap=256"
  }
}
```

## 7. 代码结构

继续使用单页原生 JavaScript，但把单一 1500 行 HTML 中的职责分开：

- `web/index.html`：语义结构与页面容器。
- `web/styles.css`：设计 token、布局和组件样式。
- `web/app.js`：状态管理、API 客户端、工作流切换和通用反馈。
- `web/workflows/*.js`：裁切、回贴、拼合、行列裁切、分辨率导出，各文件只管理自身控件和请求。
- `server.py`：保留算法与 HTTP 入口；新增统一校验、CORS、文件流式传输和安全路径工具。
- `tests/test_server.py`：参数、路径、CORS、上传、缩放和历史记录回归测试。
- `tests/test_ui_contract.py`：五个导航入口、唯一 ID、JS 引用、设计 token 和可访问性契约。

本次不拆分图像算法模块，避免界面改版同时触碰成熟算法；只将新增的安全/校验辅助函数保持小而可测。

## 8. 测试与验收

### 8.1 自动化

- 原始静态路径越界请求必须返回 403/404，不能读出 `server.py`。
- `OPTIONS` 返回 204，允许的本地来源得到正确 CORS 头，其他来源不放行。
- `overlap < 0`、`overlap >= long_edge`、总图块超限均返回 400。
- 上传超过限制、空上传、伪图片、同名上传都有确定结果且不覆盖旧文件。
- 分辨率导出在长边、短边、倍数模式下尺寸正确；超像素限制返回 400。
- 五个工作流导航都存在且能激活对应页面；“局部回贴”不再不可达。
- 所有 JavaScript 读取的 DOM ID 必须存在且唯一。
- Python 语法、JavaScript 语法和全部测试命令退出码为 0。

### 8.2 人工验收

在 1600 × 1000、1280 × 800、1024 × 768、390 × 844 四种视口检查：

- 没有横向溢出、按钮截断或不可见流程入口。
- 当前流程、当前文件、运行状态和唯一主动作一眼可辨。
- 裁切网格移动与实际 `/api/plan` 返回一致。
- 错误不需要翻到底部日志才能看到。
- 键盘可遍历导航、文件选择、输入和按钮；焦点状态清楚。

- 从干净目录构建 v0.5.0 EXE。
- EXE 启动后五个工作流全部存在，版本一致。
